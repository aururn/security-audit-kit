# 0005 キットの検出力をカナリアで確かめる

- 状態: 採用
- 日付: 2026-09-30

## 背景

最初の CI は、「キット自身をスキャンして0件」であることだけを確かめていた。
しかし、作っている途中で次の不具合があり、どれも「0件」と区別がつかなかった。

- レポートが Docker の仮想マシンの中に書かれて、手元に何も出なかった
- Linux で書き込み権限が無く、全ツールが失敗した
- Semgrep のルールセットの1つが空だった

スキャナが黙って何も検査しなくなっても、その CI は通ってしまう。

## 決定

- 各ツールが必ず1件以上検出する種を仕込んだ、小さな使い捨てのリポジトリ（カナリア）を、テストのたびに作る
  - 仕込むもの：秘密情報、既知の脆弱性がある依存、危険なワークフロー、危険なコード
- 秘密情報はテストのたびに生成し、リポジトリには残さない
- 各ツールの `status` が `ok`、かつ `count` が1以上であることを CI で確かめる
- 仕込みのファイルは `.fixture` の拡張子で置き、キット自身のスキャンでは検出されないようにする
- 各スキャナの性能（何を検出できるか）そのものは、各開発元が保証する範囲としてテストしない

## 結果

- キットの配線（マウント、権限、ツールの呼び出し、結果の集計）が壊れると CI が失敗する
- ツールの版を上げたときに、検出の仕方が変わったことにも気づける
