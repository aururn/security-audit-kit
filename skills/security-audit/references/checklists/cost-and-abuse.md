# 課金と悪用のチェックリスト

請求額 = 1リクエストあたりのコスト × リクエスト数。リクエスト数はクローラやスクリプトが勝手に増やす。
★ = 一般に見落とされがちな項目。

## 1リクエストあたりのコスト

- [ ] ★ トップページが毎回動的レンダリングになっていないか（`Cache-Control: no-store`、キャッシュ MISS）。理由を把握している
- [ ] ★ SSR で大量のデータや自分自身の公開 URL を取りに行っていない
- [ ] ★ `public/` に大きなファイルがない。本番で実際に配信されている大きさを測った
  - `find public -size +500k`、`curl -s -o /dev/null -w '%{http_code} %{size_download}' <url>`
- [ ] 認証なしで、有料の上流（LLM、画像処理、外部 API）を呼べる API を一覧にした

## リクエスト数

- [ ] `robots.txt` がある（検索に載せないアプリは全拒否）
- [ ] ★ AI クローラ対策（Vercel なら Firewall の Bot Protection / AI Bots マネージドルールセット）
- [ ] 有料の API にレート制限がある（WAF、または共有ストア。サーバーレスではメモリ上のカウンタは効かない）
- [ ] 他サイトから埋め込めない・ブラウザ経由で API を呼べない（`frame-ancestors`、送信元チェック）

## 上限と通知（ダッシュボードでしか確認できない。利用者に確認を依頼する）

- [ ] ホスティングの支出上限と自動停止（Vercel Spend Management）
- [ ] LLM・上流プロバイダの月間上限とアラート
- [ ] 通知が実際に人に届く（メール、Slack）

## 放置されたデプロイ

- [ ] ★ 検証用・デモ用のデプロイが公開されたまま放置されていない
- [ ] Preview デプロイが保護されている（Deployment Protection）
- [ ] ★ 本番がどのリポジトリ・ブランチからデプロイされているか確認した（フォークやミラーが本番の配信元のことがある）

## 事例から

AI クローラが、重いトップページ（1回あたり数 MB、キャッシュなし）を1日数十万〜数百万回取得し、
利用者のいない個人サイトで1か月約120万円の転送量課金が発生した事例がある。
原因は「動的レンダリング × キャッシュなし × 大きな応答 × 放置された公開 URL × 支出上限なし」の組み合わせで、
どれか1つを塞げば大きく減らせた。
