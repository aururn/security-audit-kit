# 監査の範囲（scope）

動的な確認（ローカルでの再現、DAST、ブラウザでの確認、本番への読み取りのリクエスト）を始める前に、
エージェントがこの文書を埋め、利用者の承認を取ります。ここに書いていない URL・操作は行いません。
この文書は監査の報告に添えます。対象のリポジトリにはコミットしません。

## 対象

- リポジトリ: <URL またはパス>
- ブランチとコミット: <branch> / <commit SHA>
- 本番がデプロイされているリポジトリとブランチ: <利用者に確認。分からなければ「未確認」>

## 動的に試してよい URL

攻撃的なリクエスト（DAST、偽の上流を使った再現、ブラウザからの攻撃ページ、入力の改ざん）を送ってよい URL です。
ローカルか、利用者が管理する検証環境だけを書きます。

| URL | 何か | 管理者 |
| --- | --- | --- |
| `http://localhost:3000` | 手元で起動したアプリ | 利用者 |

## 読み取りだけの URL

状態を変えず、課金も発生させない `GET` だけを送ってよい URL です（ヘッダ、Cookie の属性、`robots.txt`、静的ファイルの大きさ）。

| URL | 何か |
| --- | --- |
| `https://<本番のホスト>` | 本番 |

## 使ってよいアカウントと鍵

- テスト用のアカウント: <なし／ローカルで作る／利用者が用意した検証用のもの>
- 上流 API の鍵: 偽の鍵だけを使う（本物の鍵で有料の API を呼ばない）

## しないこと

- 上の表にない URL へのリクエスト
- 本番への DAST、負荷のかかるスキャン、大量のリクエスト、書き込み、LLM など有料の上流を呼ぶリクエスト
- 本物の利用者データの取得（件数の確認で足りるときは件数だけを見る）
- 秘密情報の値を、報告・ログ・Issue・PR に出すこと
- force push、履歴の書き換え、公開範囲の変更、秘密情報のローテーション（利用者が別に承認した場合を除く）
